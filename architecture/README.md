# Link Health V3：正式多账号系统建设清单

当前公开网站是演示站。**此目录仅包含待审查的数据库设计，不会自动创建云数据库或开放真实代理登录。**

## 权限与数据边界
- 平台管理员：可查看所有代理、服务订单、佣金和审核日志。
- 机构负责人：只查看所属机构的推荐订单及佣金；不能读取其他机构信息。
- 个人/保险代理：只查看自己推荐的订单和佣金。
- 代理界面使用客户代号和非敏感服务进度。患者姓名、联系方式、诊断、病历、检查报告等必须放入独立、严格授权的医疗数据系统，不与佣金表混存。
- 前端身份切换只是演示，不具备安全意义；真实权限由数据库 RLS + 服务端验证共同执行。

## 上线前必做
1. 确认运营主体、数据存储地区、涉及中国与日本的个人信息跨境处理要求，明确用户授权、留存期限、删除流程。
2. 创建由运营主体控制的云项目，开启邮箱验证和 MFA；绝不把密钥写进 GitHub 或前端。
3. 在独立测试数据库中审查并执行 `v3-schema.sql`；该 SQL 只是初稿，未经过迁移测试或生产安全审计。
4. 建立可信服务端 API：邀请代理、创建订单、按生效日期锁定佣金规则、退款冲回、审核结算、上传付款凭证。
5. 编写跨机构/跨代理越权测试、停用代理访问测试、财务并发及退款测试。
6. 对保险公司和医疗相关返点协议进行合规审查；不合规项目必须能禁止计佣。
7. 使用虚构资料完成试运行，经过验收后再逐步导入已取得合法授权的真实客户。

## 费用原则
可以先选择有免费额度的托管认证/数据库进行技术验证；正式运营时需根据实际存储、备份、安全和流量评估费用。免费套餐不等于具备医疗数据合规能力。
