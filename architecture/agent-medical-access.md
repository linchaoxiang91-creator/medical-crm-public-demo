# Link Health V3：代理备案与日本诊疗资料分级授权（需求冻结稿）

## 用户与客户归属
- 平台管理员：查看并管理全部客户、资料、进度、佣金和授权记录。
- 代理：自主录入客户基础信息，备案归属自己；只能查看本人备案且未被管理员撤销访问权限的客户。
- 客户归属在服务端写入 authenticated user id，不接受前端任意指定归属人；管理员调整归属需审计。
- 代理新增客户时先完成客户信息处理告知及合法授权；敏感健康信息需要单独、明确授权，遵守适用法域规定。

## 文件分类
1. 国内病历（domestic_medical）：所属代理可上传、读取自己客户的文件，管理员全权管理。
2. 日本诊疗报告（japan_clinical）：默认仅管理员可读取。代理即使上传文件，也不自动取得读取权限；服务端接收上传后应只返回成功状态及不敏感元数据，不返回文件内容、预览或可复用下载链接。
3. 业务进度（service_progress）：代理只看到管理员明确标记为“可向代理展示”的进度摘要，不包含诊断、治疗细节或敏感备注。

## 日本报告的临时授权
- 管理员选择“具体代理 + 具体文件 + 有效期 + 授权原因”，并可提前撤销。
- 每次查看/下载由服务端验证：登录有效、代理仍然拥有该客户的归属访问权、授权未过期或撤销、文件未被删除。
- 文件采用私有对象存储；不提供公开 URL；短效签名下载链接须在验证后生成，撤销后旧链接在短暂有效期内仍可能访问，故应设置很短的 TTL。
- 授权与访问事件记录：操作者、文件、客户、代理、时间、行为、结果；限制日志中的敏感数据。
- 不应因授权一个文件而开放整份客户档案或该客户的其他日本报告。

## 最低验收测试（使用虚构数据）
- 代理 A 无法通过 URL、API 或猜测 ID 查看 B/C 的客户和国内病历。
- 代理 A 无法查看未授权日本报告；自己上传日本报告也不例外。
- 管理员授权报告 X 后，A 只能访问 X，不能访问报告 Y。
- 授权到期/撤销、代理停用、客户转移后，所有后续 API 请求均被拒绝。
- 代理不得读取日本报告内容的搜索索引、缩略图、日志、通知或缓存。
- 代理不能自行更改权限、审批佣金或更改客户归属。
- 备份、删除、跨境传输及客户授权撤回流程需要专项测试。

## 发布约束
现有 GitHub Pages 公共演示站只允许虚构数据。正式试用须先完成私有后端、认证、数据库权限、私有文件存储、安全测试和隐私合规检查。不得将任何真实病历、姓名、联系方式或医疗报告提交到公开 GitHub 仓库。
